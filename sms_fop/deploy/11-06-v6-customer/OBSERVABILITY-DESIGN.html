Inventory Ledger v6 — Observability Design

Minimal signal set to power Grafana dashboards for monitoring, alerting, and capacity planning. One table (audit.event_log) carries every event; CDC (audit.audit_log) carries row-level changes.

Design principle

One row per thing that happened. Every row tagged with event_type, tenant_id, correlation_id, and at. That's enough for Grafana to compute counts, rates, latencies, and per-tenant breakdowns. No separate metrics tables. No periodic snapshots. Aggregations happen at query time.

FLOW INFile ingestion (files.com / SFTP)

Java daemon picks files from the remote source and lands them in staging.stocklevel_inbox. If anything goes wrong here, nothing downstream gets data.
Event we captureWhy it mattersWhat it tells us
file.picked First proof a file existed on the remote. Without this, "no data" looks the same as "no files arrived". Files/hour throughput, age at pickup, source freshness.
file.parsed Records the parse outcome: rows parsed, rows rejected, footer match, bytes. Per-file success rate, data-quality trend, parse-time p95.
file.failed Captures error code + reason when a file is quarantined. Failure rate by source/tenant, top failure reasons.

FLOW INInbound API (SFDC orders, FOP transactions)

Each inbound JSON payload lands in staging.order_inbox or staging.txn_inbox. The payload and timing are already captured — we just emit one event per arrival for Grafana to see it.
Event we captureWhy it mattersWhat it tells us
order.received SFDC sent us an order line. Includes tenant, payload size, source IP. Orders/min per tenant, payload-size outliers, peak-hour shape.
txn.received FOP sent us a transaction (shipment / return / receipt / adjust). Transaction velocity per warehouse, FOP integration health.

CALCULATEPromotion & calculation (staging → processed)

The v6 auto-promote triggers cascade staging rows into processed.* and update stock_balance. These events capture the outcome and timing of that cascade.
Event we captureWhy it mattersWhat it tells us
promotion.success An inbox row promoted cleanly. Carries inbox-to-processed latency. Drain throughput, end-to-end lag (p50/p95).
promotion.failed Promotion rejected with a reason (missing product, bad tenant, etc.). Reject rate per reason — feeds data-quality dashboard.
stock.changed on_hand or reserved moved. Includes signed delta and the trigger that caused it. Stock velocity, oversell events, stock-out events.

READ OUTATP queries (SFDC consumes)

The single biggest blind spot today. fetch_inventory_json runs but leaves no trace — we don't know who asked, how often, or how fast.
Event we captureWhy it mattersWhat it tells us
atp.queried One row per ATP call. Caller, filters used, rows returned, latency. ATP usage pattern, slow-query catch, empty-result rate (catalog gaps).

NOTIFY OUTNotifications & alerts

Already covered by processed.notification_outbox. We just need to emit one event-log row when severity is WARN/ERROR so Grafana can alert without watching two tables.
Event we captureWhy it mattersWhat it tells us
notify.emitted A WARN/ERROR was raised — back-dated OB, trigger failure, validation error. Error-rate alert source, top noisy sources, severity trend.

HEALTHSystem liveness

One periodic event proves the Java daemon is alive and connected to the DB. Cheaper than parsing logs.
Event we captureWhy it mattersWhat it tells us
daemon.heartbeat Java emits one row per minute. Absence = daemon down. Liveness probe; on-call alert source.

Proposed table

CREATE TABLE audit.event_log ( event_id BIGSERIAL PRIMARY KEY, at TIMESTAMPTZ NOT NULL DEFAULT now(), event_type TEXT NOT NULL, -- file.picked, atp.queried, ... severity TEXT NOT NULL DEFAULT 'info', -- debug | info | warn | error source TEXT, -- files.com | sfdc | fop | trigger | daemon | sql actor TEXT, -- caller id / db user / service name tenant_id TEXT, correlation_id TEXT, -- ties file → promotion → notify together status TEXT, -- ok | failed | partial | rejected rows_affected INTEGER, bytes BIGINT, latency_ms INTEGER, error_code TEXT, payload JSONB NOT NULL DEFAULT '{}' ); CREATE INDEX ix_event_log_at ON audit.event_log (at DESC); CREATE INDEX ix_event_log_type_at ON audit.event_log (event_type, at DESC); CREATE INDEX ix_event_log_tenant_at ON audit.event_log (tenant_id, at DESC); CREATE INDEX ix_event_log_corr ON audit.event_log (correlation_id) WHERE correlation_id IS NOT NULL;

What Grafana gets from this

Dashboard panelSQL shape
Files picked / hour count(*) where event_type='file.picked' group by date_trunc('hour', at)
ATP query latency p95 percentile_cont(0.95) within group (order by latency_ms) where event_type='atp.queried'
Reject rate by reason count(*) where event_type='promotion.failed' group by error_code
End-to-end lag (file pick → stock updated) join file.picked with stock.changed on correlation_id
Daemon alive? max(at) where event_type='daemon.heartbeat' > now() - interval '2 min'
Top noisy tenants count(*) where severity in ('warn','error') group by tenant_id

Intentionally out of scope

Not capturingWhy
Per-trigger execution time histograms Postgres pg_stat_statements already does this. Don't duplicate.
Periodic snapshot tables (gauges) Grafana can compute current state from the latest event of each type. Snapshots add write load for no extra signal.
Lock-wait / deadlock metrics Lives in Postgres system views (pg_stat_activity). Surface via Grafana's Postgres datasource directly.
DB connection pool saturation Java daemon (HikariCP) exposes this on its own JMX/Prometheus endpoint. Don't store in DB.
Per-row payload duplication (we already have it in inbox tables) The event_log stores a small extract (size, status), not the full payload — keeps it Grafana-fast.
Summary: 9 event types, 1 table, 4 indexes. Powers files/min, ATP latency, end-to-end lag, reject reasons, daemon liveness, error rate, and per-tenant breakdowns — all from one SQL table the Grafana team can point a Postgres datasource at directly. CDC of stock changes stays in the existing audit.audit_log (separate concern, separate shape). Easy to extend later: new event types add no schema changes.
